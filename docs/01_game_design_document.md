## 1️⃣ 核心游戏循环（Core Game Loop）

### 1.1 玩家行为循环

```
┌─────────────────────────────────────────────────────────────┐
│                    玩家行为循环                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   [探索江湖] ──→ [触发事件] ──→ [做出选择] ──→ [承受后果]    │
│        ↑                                      ↓            │
│        └──────────── [资源/关系变化] ←──────────┘            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

| 阶段 | 玩家行为 | 产出 | 世界响应 |
|------|----------|------|----------|
| 探索 | 移动、调查、采集 | 发现资源/事件 | NPC活动、区域变化 |
| 社交 | 对话、赠送、切磋 | 好感度变化 | 关系网演化 |
| 战斗 | 普通攻击、武学技能 | 胜负、资源获取 | 门派仇恨、江湖声望 |
| 经营 | 建设、修炼、合成 | 门派壮大 | 世界格局变化 |

### 1.2 成长系统

```
三维成长体系：
┌────────────────────────────────────────────────┐
│                                                │
│   【身】体质、根骨 → 生命、防御、抗性            │
│     ↓                                         │
│   【技】武学境界 → 功法威力、连击、暴击          │
│     ↓                                         │
│   【心】悟性、魅力 → 社交成功率、事件选项        │
│                                                │
└────────────────────────────────────────────────┘

武学修炼路径：
初学 → 小成 → 大成 → 圆满 → 出神入化 → 浑然天成
  ↓       ↓       ↓       ↓         ↓
实战熟练度 + 修为灌注 + 顿悟触发 + 境界突破
```

### 1.3 风险与资源循环

| 资源类型 | 获取方式 | 消耗场景 | 失败惩罚 |
|----------|----------|----------|----------|
| 生命 | 休息、丹药 | 战斗、事件 | 死亡/重伤 |
| 金钱/物资 | 交易、任务 | 购买、修缮 | 经济崩溃 |
| 声誉 | 正面事件 | 杀戮、背叛 | 门派敌对 |
| 时间 | 自然流逝 | 修炼、赶路 | 季节/寿元消耗 |
| 关系 | 社交 | 背叛、冲突 | 联盟破裂 |

## 2️⃣ 系统架构设计（System Architecture）

### 2.1 模块总览

```
┌──────────────────────────────────────────────────────────────────┐
│                         游戏主循环 (GameLoop)                      │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐              │

│  │  EventSystem│  │ BattleSystem│  │ NPCBrain    │              │
│  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘              │
│         │                │                │                     │
│         └────────────────┼────────────────┘                     │
│                          ↓                                       │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │              世界模拟系统 (WorldSimulation)                  │ │
│  │  ├── 时间管理 (TimeManager)                                 │ │

│  └─────────────────────────────────────────────────────────────┘ │

│  └─────────────┘  └─────────────┘  └─────────────┘              │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

### 2.2 各系统职责

#### 世界模拟系统 (WorldSimulation)
- **职责**：驱动游戏世界的时间流逝、区域状态、门派兴衰
- **核心数据**：`WorldState`（季节、天气、江湖动态）
- **输出**：供AI/事件系统读取的世界状态快照

#### NPC AI 系统 (NPCBrain)
- **职责**：每个NPC的决策逻辑（行动、对话、战斗）
- **组成**：
  - `GoalComponent`（目标：求生/复仇/修炼/社交）
  - `MemoryComponent`（记忆：玩家行为、关系变化）
  - `ActionSelector`（基于目标选择行动）
- **触发**：每游戏日/事件时运行

#### 战斗系统 (BattleSystem)
- **职责**：回合制/半即时战斗结算
- **输入**：双方属性 + 武学技能 + 环境因素
- **输出**：伤害结果、状态变化、资源掉落
- **依赖**：武学系统提供技能数据

#### 武学/技能系统 (MartialArtsSystem)
- **职责**：武学数据管理、修炼进度、技能释放
- **数据结构**：技能树 + 修炼路径图
- **依赖**：属性系统计算威力

#### 经济系统 (EconomySystem)
- **职责**：物品定价、资源流通、门派经济
- **机制**：基于供需的动态价格 + 门派特产

#### 事件系统 (EventSystem)
- **职责**：生成/触发/结算随机事件
- **类型**：世界事件（瘟疫、饥荒）、个人事件（奇遇、仇杀）
- **依赖**：世界状态 + NPC关系数据

#### 存档系统 (SaveSystem)
- **职责**：完整游戏状态序列化/反序列化
- **格式**：`JSON`（可读性好，便于调试）

### 2.3 系统间数据流

```
事件系统 ←────────── 世界状态快照
    ↓
玩家决策 ──→ 战斗系统 ──→ 结果结算 ──→ 关系/资源变化
    │                              ↓
    └──────────────────────────────→ 世界模拟系统（更新状态）
                                         ↓
                                    NPC AI 系统（重新计算行为）
                                         ↓
                                    存档系统（自动/手动保存）
```

## 3️⃣ 技术选型（Technical Stack）

### 3.1 Godot vs Unity 对比

| 维度 | Godot 4.x | Unity |
|------|-----------|-------|
| 授权 | MIT开源，完全免费 | 订阅制，有收入门槛 |
| 体积 | 引擎约40MB | 引擎约1GB+ |
| 2D支持 | 原生2D引擎（含像素对齐） | 依赖第三方插件 |
| 脚本语言 | GDScript（Python-like）或 C++ | C# |
| 社区 | 较小但增长快 | 庞大成熟 |
| 导出平台 | PC/Mac/Linux/Web/iOS/Android/主机 | 全平台 |
| ECS支持 | 内置Node+Resource模式 | 需要第三方库 |
| 学习曲线 | 对新手友好 | 中等 |

**结论：选用 Godot 4.x**

**原因**：
1. 独立开发者/小团队：零授权成本
2. 原生2D支持优于Unity
3. GDScript对原型开发极快
4. MIT开源，避免平台锁死

### 3.2 GDScript vs C#

| 维度 | GDScript | C# |
|------|----------|-----|
| 开发速度 | 极快（Python-like） | 中等 |
| 性能 | 接近C#（JIT） | 较好 |
| 外部库 | 有限 | 丰富（.NET生态） |
| 团队协作 | 脚本人员友好 | 程序员友好 |
| 调试 | 内置 debugger | VS集成好 |

**结论**：主用 GDScript，核心系统（如战斗AI、伤害计算）可用 GDExtension（C++）或 C# 插件。

### 3.3 数据结构设计

```
┌─────────────────────────────────────────────────────────────┐
│                     数据存储层级                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  【配置层】Resource (.tres)                                  │
│    - 武学数据、技能数据、物品数据、对话数据                   │
│    - Godot Resource格式，版本控制友好                        │
│                                                             │
│  【实例层】JSON / Godot Resource                             │
│    - 玩家存档、NPC实例、门派数据                             │
│    - 运行时生成，可序列化                                     │
│                                                             │
│  【内存层】Godot Node/Object                                  │
│    - 场景实例、运行时状态                                     │
│    - 通过SaveSystem序列化/反序列化                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**数据结构选择**：
- **配置数据**（武学、物品、NPC模板）：`Godot Resource (.tres)` + 版本控制
- **存档数据**：JSON（跨平台、可读）
- **运行时状态**：Godot内置对象

```
━━━━━━━━━━━━━━━━━━━━━━━

        ↓

━━━━━━━━━━━━━━━━━━━━━━━

│   • Idle (静止)  - 1帧                                             │
│   • Walk (行走)  - 4-8帧 SpriteSheet                               │
│   • Attack (攻击) - 6-12帧                                         │
```

### 4.3 风格统一策略

| 策略 | 执行方式 |
|------|----------|
| Style Guide | 包含：配色表、线稿风格、渲染参数、正负提示词清单 |
| LoRA 模型 | 用精选图集训练专属LoRA（约100张），后续所有图用此LoRA生成 |
| 批量生成 | 一次生成200+素材，筛选统一风格，避免风格漂移 |
| 人工终审 | 每批素材必须经过视觉一致性检查 |

### 4.4 动画方案对比

| 方案 | 适用场景 | 工具 | 成本 |
|------|----------|------|------|
| SpriteSheet | 像素风、Q版 | Aseprite手动绘制 | 高（人力） |
| Spine | 流畅动作、角色动画 | Spine编辑器 | 中（需要骨骼绑定技能） |
| 程序化动画 | 简单循环（呼吸、特效） | GDScript生成 | 低 |
| AI辅助 | 生成中间帧 | Ebsynth / 插值AI | 中（需人工修正） |

**推荐**：Spine（角色）+ SpriteSheet（特效/环境）+ 程序化（UI反馈）

## 5️⃣ MVP（最小可行版本）

### 5.1 第一阶段必须实现（6-8周）

```
核心功能清单：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【世界】
□ 地图系统：至少3个区域（新手村、中立城、敌对地）
□ 时间系统：日/季节流逝（可暂停/加速）
□ 随机事件：5-8种基础事件（战斗、奇遇、交易、对话）

【角色】
□ 玩家角色：属性（生命/内力/攻击/防御）、背包、武学装备
□ 基础属性成长：等级、经验、修炼
□ 3种基础武学（拳、剑、内功）+ 技能释放

【NPC】
□ 5-10个NPC：可对话、可战斗、可交互
□ 简单关系系统：好感度（友好/中立/敌对）
□ NPC AI：巡逻、追击、对话反应

【战斗】
□ 回合制战斗UI
□ 伤害计算：基于属性 + 武学加成
□ 胜负结算：经验/物品掉落、死亡惩罚

【系统】
□ 存档/读档（JSON）
□ 物品系统：拾取、使用、丢弃
□ 基础UI：HUD、背包、对话、技能栏
```

### 5.2 明确不做的内容（避免膨胀）

```
✗ 主线剧情（系统驱动，事件即内容）
✗ 完整江湖地图（先做3个区域原型）
✗ 门派建设/经营（Phase 2）
✗ 复杂关系网（Phase 2再扩展）
✗ 多人/联机功能
✗ 完整中文本地化（先用英文/假名开发）
✗ 音效/配乐（Phase 3）
```

### 5.3 开发周期估算

| 周次 | 任务 | 交付 |
|------|------|------|
| 1-2 | 项目搭建、引擎熟悉、核心架构 | 空项目 + 架构草图 |
| 3-4 | 世界/地图系统、时间系统 | 3个可探索区域 |
| 5-6 | 玩家角色、NPC系统、对话 | 可交互NPC |

| | 存档文件损坏 | 低 | 高 | JSON校验 + 自动备份机制 |

| | 系统间耦合过高 | 中 | 中 | 严格模块化，数据通过接口传递 |
| | 内容深度不足 | 高 | 中 | Phase 2聚焦深度而非广度 |
| **AI美术流程** | 风格不一致 | 高 | 中 | Style Guide + LoRA强制统一 |
| | Prompt依赖人工修正 | 高 | 低 | 建立修正库，持续优化Prompt模板 |

| | AI美术成本超预期 | 中 | 低 | 优先使用开源模型，控制生成数量 |
